# Authenticated comment subtree deletion contract

Standard DELETE `/api/sites/{siteId}/comments/{commentId}` requires `comments.manage` with fresh canonical site authorization even though the path is under the site API. SDK `deleteComment(commentId, options)` now accepts site override, session, cookies and request correlation. Existing one-argument calls remain supported. Private original deleted comment data is administrative data; every response is no-store.

HTTP200 includes the exact deleted subtree and count, legacy root mirrors, required `data.completionWarnings:string[]` and `data.concurrencyBoundary` (`database-site-row-lock` or `demo-single-process`). `COMMENT_AUDIT_PENDING` records safe postcommit audit follow-up while retaining200. No automatic audit retry or deployed acceptance is implied. Wrong-site/missing root404, malformed/cyclic/cross-target tree or changed parent409, incomplete inventory/unsupported lifecycle503. Unexpected precommit errors remain sanitized500. Public page/blog reply operations and operator reparent also advertise409 current-parent/thread conflict. No request identity or moderation authority was added for visitors.

Backend PostgreSQL row-lock/atomic subtree and strict demo persistence proof is tracked separately in the comment lifecycle freeze. The demo boundary is one process. `test:comment-lifecycle-contract` executes actual DELETE with controlled atomic-adapter mocks and validates the exact standard schema, auth, projection, warnings and failures; it does not itself prove transaction semantics. SDK `test:comment-delete` and `test:comment-delete-types` verify private transport, warning preservation, no replay and exact generated DTO parity. Moderation PATCH postcommit outcomes are a separate evolving batch.
