# Private media recovery API contracts

Standard OpenAPI and SDK expose authenticated GET `/api/admin/sites/{siteId}/media/storage-recovery` (`media.view`) and POST `/api/admin/sites/{siteId}/media/storage-recovery/{jobId}` (`media.edit`). Central canonical site grants remain authoritative. GET supports limit1–100 (default50), nonnegative offset and pendingOnly true/false (defaulttrue). POST accepts a UUID job identifier and no cleanup path/body. Administrative results are no-store;503 responses advertise Retry-After1.

List DTOs contain safe identity, status, operation and byte/file/attempt counts with sanitized error codes. Private planned paths, provider destinations, credentials and raw failure messages never belong in these DTOs. Explicit retry returns pending/settled and deleted/protected/remaining counts plus usedBytes. HTTP200 pending does not certify cleanup: pending unreferenced bytes remain reserved against quota. Surviving originals, variants and retained versions are protected by full inventory before deletion. Missing/wrong-site jobs return404; invalid UUID/pagination400; unavailable journal/inventory/destination changes503 retain journal/files. Durable provider uncertainty may also block ordinary writes/site deletion. Journal plan limits409 and scoped site/job absence404 remain error-envelope semantics in existing writers.

SDK methods `adminMediaStorageRecovery(siteId, query, options)` and `retryAdminMediaStorageRecovery(jobId, options)` preserve session/cookies, site scope and request IDs; they do not automatically replay cleanup after errors. No configured privileged cleanup worker is promised. PostgreSQL admission versus single-process demo boundary is explicit in the list response. Backend journal/local-byte/isolated PostgreSQL evidence is recorded separately in the media recovery freeze report; deployed or real object-storage provider acceptance is still separate.

`test:admin-media-recovery-contract` validates actual operator routes and shared projection helper with controlled journal/reconciler mocks, safe DTOs, pending/settled states, early auth, queries, scope and errors. SDK `test:media-recovery` / `test:media-recovery-types` cover private transport and generated parity. These tests do not delete provider objects or certify SQL/recovery algorithms themselves.
