# Authenticated site lifecycle contracts

Seven existing site methods have standard OpenAPI operations and generated SDK DTOs: site GET/PATCH/DELETE, duplicate POST, readiness GET, custom frontend starter GET and connection POST. Administrative responses are private/no-store through the served admin proxy. Central request-time session/key site policy remains authoritative; site detail/update/delete also check team view/manage scope. Owner-wide access is deliberate. Selected-site credentials cannot obtain workspace `sites.create` merely by choosing a duplication source.

Site PATCH changes authored metadata/settings. The sole commentPolicy settings patch uses `comments.configure`; other patches use `sites.configure`. `settings.frontendDesign` must use its dedicated history endpoint. Unknown safe settings JSON remains extensible. Provider/mail configuration, a domain string, published status, or deployment metadata does not provision DNS, mail, a deployment or a live custom website. Confirm those prerequisites separately through their actual provider/control-plane routes.

Duplication creates an unpublished draft and copies pages with nested editable content, parent and navigation page references. It resets custom domain, domain verification, deployment and billing state. Complete canonical source page inventory is validated before destination creation; incomplete/malformed/foreign inventories return503 `SITE_DUPLICATION_INVENTORY_INCOMPLETE` without writes. Copy application remains sequential: a later failure may leave a destination/partial pages. This is not a transactional whole-site clone of commerce, media, submissions or all module records. Existing source/demo forms references may be copied by the implementation.

Readiness inventories pages/posts/collections/media/reusable sections completely with validated pagination; errors return503 `SITE_READINESS_INVENTORY_INCOMPLETE` and no-store. A score is a content/configuration assessment, not browser, mail, DNS, provider or deployment certification. Demo complete paginated post/media reads remain synchronous.

DELETE is destructive. The route refuses pending storage recovery or remaining managed storage references with409, and refuses unresolved private form attachment cleanup with409/503. It performs audit/webhook work before deleting content; provider/domain deprovision is not promised. PATCH and duplication still have postcommit side effects which may fail after content is stored; do not infer rollback from every500.

Starter export returns the checked complete file-list plus site-specific public environment files; it neither writes another repository nor deploys. Copy public API/site/host values only. The connection checker fetches a public URL and its public connection probe after URL/DNS safety checks, with manual redirects/timeouts. It returns200 even when `data.status` is failed and sanitizes probe fields. Source marker/probe checks are not live DOM/interaction certification.

Proof: `npm run test:admin-site-lifecycle --workspace @backy/public` exercises actual seven handlers against an isolated real demo store and a store-backed repository adapter with schema validation, early auth/team denial, canonical identity, authored nested content, draft copy/parent remap, exported files, URL safety and guarded deletion. DNS/fetch and deletion cleanup guards are controlled fixtures. `test:site-readiness-inventory` exercises actual helper/route beyond capped inventories and failure classes. `test:site-duplication-preflight` proves refusal before destination writes. SDK `test:site-lifecycle`, `test:site-lifecycle-types` verify private transport and generated parity. These are separate from SQL, browser, real provider, DNS and deployed proof.

## Atomic duplication and retained delivery evidence (2026-10-06)

Duplication now commits site/pages/hierarchy/navigation together and returns required `pagesCopied`, `copiedResourceScope`, `concurrencyBoundary` and `completionWarnings`. Settings/theme/pages are copied; resource records and uploaded bytes are not. Authored references remain references. The Sites UI shows the count immediately and discloses this boundary. `SITE_DUPLICATION_AUDIT_PENDING` after commit returns201 and must not trigger duplication again. PostgreSQL admission protects source inventory and competing quota/slug writers; demo guarantees are single-process. Unconfirmed demo persistence requires reload/investigation, never automatic replay.

Normal creation, duplication and final backup restore enforce the configured site quota at admission/commit; a denied restore retains its recovery job. Site deletion now refuses retained private comment delivery evidence (including terminal rows) with409, or incomplete verification with503. No evidence purge workflow exists. Local/database/browser acceptance and deployment/provider certification remain distinct.
