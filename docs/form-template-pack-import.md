# Reviewed form template pack import

The Forms template library now imports its existing `backy.form-template-pack.v1` JSON export. It copies complete form fields/settings and the frontend template's standalone captured editor layout. It creates new **inactive, unattached** forms; it never replaces an existing form or activates a submission endpoint.

`POST /api/admin/sites/{siteId}/forms/template-pack/import` accepts `action: review | apply`, the pack, and explicit `selection` IDs (`builtin:<manifest.id>` or `frontend:<template.id>`). Optional `names`, `references` and `acknowledgeUnverified` default to empty objects/false. Apply requires the exact `reviewVersion` returned by review (`form-pack-v1:` followed by 64 lowercase hex characters). All responses use the canonical `success/requestId/data` envelope and private/no-store caching. The shared current-session/service-key authorization applies on every request.

Review requires `forms.view`; apply additionally requires `forms.create`. Selected forms' live references require `collections.view` during review and `collections.edit` during apply, `media.view` for media, and `pages.view` for page/post/component registry references. Explicitly supplied mapping tables also require their corresponding read permissions. Unselected templates' references do not add permissions. URL site aliases are resolved to a canonical site ID; source pack site metadata is provenance only.

Reference maps have keys `collections`, `pages`, `posts`, `media`, `components`. Values must be canonical existing destination IDs. Known live `collectionId/pageId/postId/mediaId/assetId/fontId/fontMediaId/posterMediaId/fileMediaId`, declared assets and managed upload URLs are validated/remapped; component source keys use `componentKey@version` and require active approved destination identity. Source attachments `pageId/postId` on a form manifest block standalone import. Unresolved, foreign, mismatched, invalid collection-field maps and malformed captured trees produce exact target/path findings. Unknown element types are retained with an unverified finding; registered interactive/code components missing identity/version block import. Captured custom code/styling and mapped component behavior remain explicitly **unverified**, requiring acknowledgment and actual frontend testing before activation. No supplied URL is fetched or code executed during review.

Bounds: 2 MiB request, 60,000 JSON values, depth 64, at most 64 templates/selections, 128 fields per form, 10,000 elements per captured tree, 20,000 existing destination forms, 64 destination names, 512 entries per reference table. Field keys are unique lowercase identifier keys with declared supported form types/rules. Unsafe prototype keys, accessor/non-JSON values, credential fields and URL credentials are rejected. Safe field/settings/tree JSON extensions are preserved. The full safe source manifest, template and site provenance are copied to `settings.formTemplateImport`; source manifest metadata has no destination authority. Unknown manifest root fields are retained in that complete provenance copy, rather than becoming new database columns. Copied layout form IDs/default block props are rebound to the new inactive form ID. The `frontendDesignTemplateId` remains source provenance; the standalone layout editor reads the copied elements/document, without requiring a source-site template registry.

Review fingerprints the exact safe package, selected names/mappings/acknowledgment, canonical site/form inventory, mapped current resources and relevant current billing policy. Apply repeats review inside admission. Name collisions, blocked quota and invalid mappings cannot overwrite or silently rename forms. `409 FORM_TEMPLATE_REVIEW_STALE` requires a fresh review after package/selection/current-state drift. `422 FORM_TEMPLATE_REVIEW_BLOCKED` requires resolving findings. Malformed input is 400; excessive payload is 413; incomplete current inventory or missing atomic capability is 503. Precommit unexpected failure is sanitized 500.

PostgreSQL import uses `forms.withTemplatePackImportLock`: a SERIALIZABLE transaction, canonical site row lock, fresh inventory/resource reads, all form creates and bound-layout updates. Late failure rolls back the entire batch. Wrapped SQL serialization/deadlock/unique conflicts map to safe 409. Other database adapters refuse apply, with no read/update fallback. Demo admission is synchronous within one process: strict current snapshot, preparation, one exclusive temporary file write/fsync/readback/rename, then memory publication. Unrelated persisted root fields survive. This is **not cross-process demo isolation**. Postcommit audit failure retains 201 with `FORM_TEMPLATE_AUDIT_PENDING`, without claiming a durable retry queue.

The file panel invalidates review on file/site/name/selection/reference/acknowledgment changes, aborts stale requests, shows exact selected targets and findings, and requires a separate concrete confirmation. The captured layout wrapper uses the shared CanvasEditor save callback and stable form identity, preserving editing sessions across autosaves. Ordinary form field saves preserve safe unknown field JSON through both the admin payload builder and server parser.

## Evidence and boundaries

- `npm run test:form-template-pack-import --workspace=@backy/public`: actual handler/helper/demo store, safe JSON/bounds, exact intent, field/settings/tree/root-store preservation, reference denial, current actual shared site grants, unsupported adapter, staging failure rollback, separate cold-process reopen and postcommit audit warning. Auth/provider dependencies are fixture boundaries.
- `npm run test:form-template-pack:postgres --workspace=@backy/db`: always creates and cleans its own socket-only PostgreSQL cluster and applies actual migrations; second-insert failure rollback, fresh destination conflict, canonical inactive standalone persistence, foreign reads, two independent same-review writers, and unsupported adapter refusal. It accepts no configured database URL/arguments.
- `npm run test:form-layout-persistence --workspace=@backy-cms/admin`: actual wrapper callback and shared serializer preserve canonical assets/tokens/bindings/interactions/SEO, CSS/JS, locale/version, unknown root/settings fields while saving edited elements. React/API transport are mocked; browser/disk proof is separate.
- `npm run test:admin-forms --workspace=@backy/public`: existing actual-handler/schema regression.
- Disposable browser fixture: `npx tsx --tsconfig apps/public/tsconfig.json apps/admin/scripts/form-template-pack-browser-fixture.mts`. CUA native file chooser selected the exported synthetic file, reviewed/confirmed/imported, opened the copied nested layout with source registry absent, edited its heading, manually saved through the actual detail PATCH and reloaded. A separate cold process read the edited persisted tree with unknown fields/settings and responsive override retained. Screenshot: `/tmp/backy-form-template-pack-reopen.jpg`.

The browser fixture mounts the production import/layout components and real demo handlers, with a synthetic local session and disposable store; it is not proof of the entire authenticated Forms route in a deployed environment or PostgreSQL browser transport. Provider delivery, activation/publishing, arbitrary custom React/runtime compatibility and cross-process demo writes are separate boundaries. Normal form PATCH retains its existing concurrency model; this batch proves atomic reviewed import, not an unrelated general form-save CAS redesign.

## AI/client contracts

The site OpenAPI exposes `reviewOrApplyAdminFormTemplatePack` and exact request/review/apply schemas. SDK methods `reviewAdminFormTemplatePack` and `applyAdminFormTemplatePack` use authenticated selected-site requests; apply requires `reviewVersion` in TypeScript. Optional names/reference maps/acknowledgement default as documented by the handler. Stale409 requires review again; the SDK never replays apply automatically.

Actual handler acceptance now validates success envelopes against these OpenAPI schemas. A malformed imported title remains a blocking finding and is retained in provenance, while the review target displays a string fallback. SDK transport/type tests are separate from the browser, database and provider gates.
