# Persisted identity admission for public comments

Both page and blog intake use the canonical site's persisted identity blocklist at database creation admission. `comments.create` requires PostgreSQL and acquires the existing site row lock shared by comment creation, moderation, blocking and unblock. Within that transaction it checks the normalized submitted email and IP identity against same-site blocklist type/value before insertion. Legacy blocklist row IDs do not bypass the check. Foreign-site identities do not deny another site's intake. A blocked identity returns safe `422 COMMENT_IDENTITY_BLOCKED`; unsupported adapters return `503 COMMENT_SUBMISSION_UNAVAILABLE`. Neither creates a comment nor exposes the private block reason.

The public database classifier explicitly skips only the demo identity map. The request body cannot set this trusted server option. Other classification, CAPTCHA, attribution, site policy and existing official-publication authorization remain in their established intake paths. Demo retains its persisted local block lookup by default. The database identity check also applies when an admitted moderator requests immediate publication; that intent does not bypass an identity block.

Concurrent block/unblock and creation are ordered by the existing site admission lock. A creation waiting behind a committed block is rejected; creation waiting behind a committed unblock can proceed. A creation admitted before a later block can finish, and that later block controls subsequent submissions. Prior admitted authored comments are preserved. Allowed committed submissions retain existing private projections and completion warning behavior for activity/delivery failures.
